# 数据用量核对与结算

用量事件经双方核对后进入结算。计费使用精确十进制、合同周期、保底及阶梯，账单和费率审批保持独立。

## 多变量用量监测（仅诊断）

`monitor.fit` 在双方声明完整的业务日上训练可冻结的 PCA 用量关系模型：训练、阈值校准、监测三段按时间分开，缩放只在训练期拟合，主成分数兼顾训练解释方差与前推重建误差，阈值取自独立校准期的经验分位并记录可达到的尾部精度。只有双方完整性声明仍然有效、无争议且早于知识截止的日子才进入矩阵；确认完整的空日记零，未到齐与争议日只排除、不补低消费。`monitor.scan` 把新数据投影到冻结模型，给出子空间 T² 与残差 SPE、各计量项标准化偏差、重建值与残差贡献，以及联合告警口径和校准期实际表现；阈值不在告警数据上调整。`monitor.get`/`monitor.versions` 查看冻结产物（训练矩阵、缩放、载荷、特征值、阈值）与原始用量血缘，主动重训才产生新版本。告警仅为人工复核线索，不判定错账、不改写费用；单计量项检查入口 `anomaly.outliers` 保持不变。

运行需要 Python 3.11 或更高版本，使用标准库与 SQLite，无需第三方包。演练中的机构、人员、交易及读数全部为本地合成数据。

## 构建与测试

```sh
python3 -m compileall -q meterbook
python3 -m unittest discover -s tests -v
```

## 本地运行

```sh
python3 -m meterbook replay fixtures/settlement.json
python3 -m meterbook --help
```

演练使用临时数据库，不会连接远程服务。命令以 JSON 显示业务结果；测试覆盖核心状态、边界输入和错误路径。运行前可用 `python3 --version` 核对解释器版本。
